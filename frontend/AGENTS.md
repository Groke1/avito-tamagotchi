# 🤖 Правила и контекст для AI-Агентов (AGENTS.md)

Вы — senior-разработчик в команде, создающей проект «Тамагочи Авито» на хакатоне. Ваша задача — генерировать чистый, безопасный и поддерживаемый код, строго соблюдая архитектурные ограничения проекта.

## 1. Главные правила и контекст проекта

1. **Продукт:** Игровая система мотивации/лояльности «Тамагочи Авито». Визуальный стиль и награды тесно связаны с продуктами Авито (Доставка, Автотека, категории объявлений).
2. **Контракт API:** Все сущности, эндпоинты и типы СТРОГО соответствуют OpenAPI спецификации из `docs/api-spec.yaml`.
3. **Безопасность и Git Flow:** Никакого копирования секретов в код. Все коммиты делаются с понятными названиями (Conventional Commits).

## 2. Стандарты Frontend (React 19 + TypeScript + Vite 8)

### Архитектура: Feature-Sliced Design (FSD)

Вы ОБЯЗАНЫ соблюдать FSD-слои при генерации новых файлов:

- `src/app`: Глобальные провайдеры (Redux Store, Router, Styles).
- `src/pages`: Компоненты страниц. Не содержат сложной бизнес-логики.
- `src/widgets`: Компоновка из features и entities (например, `PetCardWidget`, `DailySummaryWidget`, `Header`).
- `src/features`: Изолированные действия пользователя (кнопка «Покормить», кнопка «Взять награду», «Склонировать промокод»).
- `src/entities`: Модели данных, селекторы и базовые UI-карточки бизнес-сущностей (`Pet`, `Reward`, `User`, `Leaderboard`).
- `src/shared`: Атомарные UI-компоненты (`Button`, `Modal`, `Card`, `Badge`), утилиты (`clsx`, `tailwind-merge`), базовые API-клиенты.

⚠️ **Правила FSD:**

1. **Иерархия импортов:** Слой импортирует только из нижележащих слоев (`pages` -> `widgets` -> `features` -> `entities` -> `shared`). Импорты снизу вверх и между модулями одного слоя ЗАПРЕЩЕНЫ.
2. **Public API (`index.ts`):** Каждый слайс ДОЛЖЕН иметь `index.ts`. Все внешние импорты идут ТОЛЬКО через Public API. Глубокие импорты (напрямую в файлы внутри слайса) строго ЗАПРЕЩЕНЫ:
   - ❌ `import { PetCard } from '@/entities/pet/ui/PetCard'`
   - ✅ `import { PetCard } from '@/entities/pet'`
3. Используйте алиас `@/*` для импортов.

### Стейт-менеджмент и Запросы (RTK Query)

- Запросы к API реализовывать ТОЛЬКО через **RTK Query** (`@reduxjs/toolkit/query/react`).
- Типизация ответов и запросов берутся строго из `docs/api-spec.yaml`.
- Экшены взаимодействия с питомцем (`POST /pet/feed`, `POST /pet/play`, `POST /pet/rest`) должны корректно обрабатывать ошибку HTTP `429 Too Many Requests` (Rate Limit) и выводить предупреждающий Toast.

### Стилизация и UI-компоненты (shadcn/ui + Tailwind CSS v4)

- В качестве базовой UI-библиотеки используется **shadcn/ui** (New York style / Slate).
- Все атомарные примитивы shadcn (`Button`, `Dialog`, `Progress`, `Card`, `Toast` и т.д.) располагаются СТРОГО в слое **`src/shared/ui/`**.
- Главная утилита объединения классов `cn()` находится в **`src/shared/lib/utils.ts`**.
- Иконки берем исключительно из библиотеки **`lucide-react`**.

## 3. Особенности взаимодействия с Backend и WebSocket

1. **Авторизация и Онбординг:**
   - После `POST /auth/register` или `/auth/login` токен сохраняется в App State.
   - **401 Unauthorized:** При получении ошибки `401 Unauthorized` на любом эндпоинте — сбрасывать токен в Redux State и автоматически перенаправлять пользователя на экран `/login`.
   - Запрос `GET /pet` при первичном входе пользователя возвращает `404 Not Found`. Фронтенд ДОЛЖЕН обрабатывать 404 и направлять на экран создания питомца (`POST /pet`).
2. **WebSocket Connection:**
   - Для открытия WS-соединения фронтенд сначала делает запрос `POST /ws/ticket`, получает разовый тикет, и затем подключается к WS с этим тикетом в query-параметре (`/ws?ticket=...`).
   - Предусмотреть обработку auto-reconnect при потере соединения.
3. **Промокоды и Награды:**
   - Полученные промокоды (`promo_code`) выводятся с возможностью быстрого копирования в буфер обмена и анимацией подтверждения скопированного состояния.
