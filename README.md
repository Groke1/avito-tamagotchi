# Avito Tamagotchi

> Геймификационный сервис, который связывает игровой прогресс
> пользователя с его активностью внутри Авито.

**Сайт:** http://avitotam.ru/

## Описание проекта

**Avito Tamagotchi** --- геймификационный сервис, в котором пользователь
получает виртуального питомца, ухаживает за ним, выполняет задания,
получает опыт и награды и развивает питомца.

Задания связаны с различными сценариями Авито: просмотром объявлений,
добавлением товаров в избранное, публикацией объявлений и другими
действиями.

Основная идея проекта --- превратить игровые механики в дополнительную
мотивацию для регулярного взаимодействия с Авито.

## MVP

-   Регистрация и авторизация пользователей через JWT.
-   Создание питомца и главный экран с его текущим состоянием и
    характеристиками.
-   Механики взаимодействия с питомцем: кормление и поглаживание.
-   Система заданий, связанных с активностями Авито.
-   Получение опыта и монет за выполнение заданий и взаимодействие с
    питомцем.
-   Система опыта и уровней: накопленный опыт повышает уровень питомца,
    а за повышение уровня пользователь получает награды.
-   Система ежедневного стрика с дополнительным опытом за
    последовательные входы.
-   Система персональных наград для пользователей.
-   Зависимость счастья от сытости питомца и дебафф к получаемому опыту
    при низких показателях.
-   Изменение состояния питомца со временем в реальном времени.
-   Общий лидерборд по уровню и опыту.
-   Еженедельный лидерборд по полученному за неделю опыту.
-   Ежедневный отчёт: полученный за день опыт, выполненные задания,
    полученные и использованные награды.

## Особенности реализации

### Хранение сессий

**User Service** может хранить сессии как в `Redis`, так и в
`PostgreSQL`. По умолчанию используется `Redis`.

Хранилище выбирается переменной окружения:

``` env
SESSION_STORE=redis
```

Допустимые значения: `redis` или `postgres`.

### Система опыта и уровней

Опыт начисляется за игровые действия и выполнение заданий. При
достижении необходимого количества опыта питомец повышает уровень, а
пользователь получает соответствующую награду.

### Изменение состояния питомца

Сытость и счастье питомца изменяются со временем. Текущее состояние
рассчитывается относительно времени последнего обновления, поэтому
постоянно записывать изменения в базу данных не требуется.

### Ежедневный и недельный прогресс

Для отслеживания активности отдельно сохраняются данные об опыте,
полученном за день. На их основе формируются недельный лидерборд и
ежедневная статистика пользователя.

### Лидерборды

Поддерживаются два типа рейтингов:

-   **общий** --- по текущему уровню и опыту;
-   **недельный** --- по количеству опыта, полученного за текущую
    неделю.

## Архитектура сервисов

### User Service

Отвечает за **аутентификацию, управление профилем и игровую экономику
пользователя**.

Основные функции:

-   регистрация, авторизация и управление JWT-сессиями;
-   хранение профиля и баланса монет;
-   отслеживание ежедневного streak;
-   управление персональными наградами и промокодами;
-   формирование ежедневной статистики пользователя;
-   взаимодействие с **Tasks Service** и **Pets Service** для получения
    данных о выполненных задачах, XP питомца и начисления бонусов.

Основное состояние хранится в **PostgreSQL**. Для хранения
refresh-токенов также может использоваться **Redis**. Refresh-токены не
сохраняются в открытом виде: в базе хранится только их SHA-256-хэш и
срок действия.

Каждая награда привязывается к конкретному пользователю. При создании
награды генерируется уникальный промокод, который сохраняется вместе с
`user_id`. При использовании награды сервис получает идентификатор
пользователя из access-токена и проверяет, что промокод действительно
принадлежит ему.

### Pets Service

Отвечает за **управление виртуальным питомцем и основными игровыми
механиками**.

Основные функции:

-   создание и хранение состояния питомца;
-   управление показателями сытости, счастья, XP и уровня;
-   взаимодействие с питомцем: поглаживание и кормление за монеты с
    таймаутом;
-   автоматический расчёт снижения характеристик питомца с течением
    времени;
-   начисление XP, повышение уровня и выдача наград;
-   формирование глобального и недельного рейтингов питомцев;
-   взаимодействие с **User Service** для списания монет и выдачи
    наград;
-   отправка изменений состояния питомца на frontend в реальном времени
    через **WebSocket**.

Состояние питомцев и ежедневная статистика XP хранятся в **PostgreSQL**.
Для взаимодействия с клиентом используются REST API и WebSocket.

### Tasks Service

Отвечает за **генерацию ежедневных заданий, отслеживание их выполнения и
начисление наград**.

Основные функции:

-   генерация случайного набора ежедневных задач при первом запросе
    пользователя;
-   получение текущих и выполненных задач;
-   отслеживание статуса выполнения задач;
-   защита от повторного выполнения задачи и повторного получения
    награды;
-   начисление монет через **User Service** после выполнения задания;
-   начисление XP питомцу через **Pets Service**;
-   предоставление внутренних API для получения истории выполненных
    задач;
-   JWT-аутентификация пользовательских запросов.

Задачи и прогресс пользователей хранятся в **PostgreSQL**, а
взаимодействие с **User Service** и **Pets Service** выполняется через
HTTP.

### Frontend

Отвечает за **пользовательский интерфейс и взаимодействие с
backend-сервисами платформы**.

Основные функции:

-   регистрация и авторизация пользователей;
-   отображение состояния питомца и взаимодействие с ним;
-   отображение и выполнение ежедневных задач;
-   просмотр и получение наград;
-   отображение глобального и недельного рейтингов;
-   отображение ежедневной статистики пользователя;
-   управление состоянием приложения через **Redux Toolkit / RTK
    Query**;
-   взаимодействие с **User Service**, **Pets Service** и **Tasks
    Service** через API;
-   получение обновлений состояния питомца в реальном времени через
    **WebSocket**;
-   автоматическое обновление access-токена при истечении авторизации;
-   разграничение публичных и защищённых страниц.

Frontend построен на **React + TypeScript** с архитектурой
**Feature-Sliced Design (FSD)**. Для стилизации используются **Tailwind
CSS** и **shadcn/ui**, для маршрутизации --- **React Router**, а сборка
выполняется через **Vite**.
